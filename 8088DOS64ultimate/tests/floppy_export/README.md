# Standalone native floppy export prototype

This opt-in fixture executes actual linked 6502 assembly in Peddle. Its independent file model supplies Ultimate DOS file contents through the existing functional UCI register model; it never supplies target RAM or REU bytes directly. No target disk data travels through FTP or a host export implementation.

Build with `python3 build_support/build_floppy_export.py`; execute with `zig build floppy-export --summary all` after registering `tests/floppy_export/build.zig` as described in `docs/FLOPPY_EXPORT_PROTOTYPE.md`. Products go to normal `build/`. The PRG has a disabled looping entry: loading or running it cannot issue a storage operation. Tests call the linked routines explicitly.

`dos64_export_init/start/poll` use native caller-owned UCI, FILE and REU primitives. The caller attests paused guest disk activity and owned destination with A5 bytes, chooses whole-image slot A=$100000 or B=$180000, and supplies an absolute NUL-terminated path of 2..128 bytes. Start rejects an open/unknown Ultimate file handle; it never blindly closes somebody else's file. The path/configuration and source REU image are immutable while busy. These attestations are not yet connected to production runtime leases, media generations or UI capabilities.

The native state machine creates a new file with mode6 (CREATE_NEW|WRITE), transfers exactly720 sectors from REU to the command buffer, closes, reopens with mode1 (READ), requires a fresh successful FILE_INFO declaring exact LE32 size368640, compares every returned byte against REU, requires zero bytes from a one-byte EOF probe, then requires final known CLOSE. A successful WRITE status has unknown actual count, and CLOSE does not establish persistence; the first possible verified publication is after fresh declared metadata, reopened content, EOF and final closure. The native code never writes REU, deletes a file, renames a file, requests truncation or marks a guest disk clean.

Every failure retains `uncertain=1`, `verified=0`, the source REU image and output path. First-failure phase, sector, FILE error and transport error are captured before the one cleanup CLOSE can overwrite diagnostics. Cleanup failure leaves an explicit unknown handle. A cancelled active transaction finishes bounded UCI abort recovery before CLOSE; an elapsed hard bound terminates immediately with unknown ownership when needed. Do not reuse that owner without external reset/recovery. A retry must use a fresh destination; prior partial/uncertain output remains available for investigation.

`now` is a caller-supplied monotonic 16-bit time, with gaps less than8000h. A 32-bit total budget defaults to144323 ticks (approximately600 PAL seconds with4096 PHI2/tick); the caller must provide the actual clock. This standalone fixture does not include a production native clock/scheduler or treat Peddle cycles as elapsed time. File transactions separately use existing UCI modular deadlines. Each poll performs bounded transport work, one512-byte DMA or one256-byte compare; no fixed-delay pacing or poll-count timeout is used.

The functional model deliberately exercises silent short writes with successful status, read corruption/shortness/extra data, file-status failures, unknown cleanup, stuck firmware, partial DMA and cancellation. It is not a filesystem, REU bus timing or power-failure durability oracle. Physical installed-firmware save/reopen and IEC persistence remain unaccepted. Existing DOS boot/builtins proofs remain separate; this fixture does not change DOS, INT21h, FAT or guest loading.

The specialized bridge derives from the project's original Peddle bridge and adds only an explicitly enabled independent export model. Existing model headers and Peddle sources are normal-path dependencies pinned in the package manifest; no ROM, DOS image or external binary test fixture is redistributed.
