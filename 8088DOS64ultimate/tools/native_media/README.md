# Native runtime media assets

`make runtime-media` builds the actual runtime and its 56 KiB disk-menu container from project sources. Python, make, cc65, ca65, ld65 and cc65 none.lib are required. No DOS image, vendor program, Peddle, Zig, C++ compiler, private checkout or hardware connection is used. Tool overrides are DOS64_MAKE, DOS64_CC65, DOS64_CA65, DOS64_LD65 and DOS64_CC65_LIB. DOS64_RUNTIME_MEDIA_ARGS may supply `--out` with an empty or builder-owned output directory.

The normal default profile remains separate. The optional runtime enables DOS64_MODAL_MENU, DOS64_SAVE_HD_CONTEXT, DOS64_EXPORT_CRC, DOS64_SAVE_MODAL and DOS64_MEDIA_BINDING. A clean owned native tree is built; every executable media phase is relinked using actual runtime and broker labels. The runtime SAVER is included explicitly. Native-only build never creates or uses a UNIT sidecar. Do not infer a runtime profile by renaming a unit binary or sharing its aliases.

Source organization: ui is the native C keyboard/display frontend; broker owns paused cache/C/clock lifetime; bridge consumes private frontend intents; controller sequences workers; phase contains selected Save and WIRE/PLAN/wrappers; binding contains common Save/Insert binding source; worker is the readonly incoming-image verifier; finish closes C and blocks Resume. The `fixture_init` symbol names are historical ABI labels for actual initialization code, not imported test fixtures. All generated aliases, C assembly, packing tables and distinct Insert binding/support are per-run products.

Build result: `build/runtime-media/RESULT.json` points to immutable run/products, including DOS64.PRG, DOS64.REL, DOS64.MNU, DOS64.labels/map, native memory verification, header and phase inventory. Source/tool/resource identities and before/after products remain in the run. All products are verified before an atomic RESULT replacement. A failure/interrupt retains the prior passed pointer/products and writes separate failure evidence when possible. A failed lock unlink retains the lock rather than pretending cleanup succeeded.

DOS64.MNU is exactly 57344 bytes: first 24576 map to REU 3DA000 and next 32768 to 3F0000. Its 64-byte D64M header and native compiled expected header bind the same fresh source cohort. This builder does not configure a launch folder, create disks, generate START recovery assets or dispatch hardware. The cold release builder must bind this actual native/MNU pair into matching START.TPL/REL/INO/RCV/RFW and verify all eight assets. No V1 or physical acceptance follows from successful compilation.

Direct Make flag switches are not an incremental cross-profile contract. Use this fresh-owned-tree builder for the enabled profile. Ordinary default runtime and unit bytes are separately checked. Optional FORMAT is deliberately not enabled here until the matching runtime-only profile is independently qualified.
