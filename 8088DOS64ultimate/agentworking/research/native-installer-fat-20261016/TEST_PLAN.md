# Independent acceptance matrix

No listed native tests have been implemented or executed by this research task. Existing Python population/inspector tools supplied only the observed sizing experiments.

* Pure C arithmetic/metadata: both exact profile headers, CHS/LBA agreement,16MiB offset seam and20MiB EOF; FAT12 odd/even entry and offset511 boundary, FAT16 last legal entry, mirror equality, root512-entry limit, zero-length files, exact cluster seams, no size multiplication wrap; directory dot/parent entries/multicluster chains, invalid/colliding short names, file/directory conflicts, capacity/descriptor/depth bounds. Assert source images byte-identical.
* Actual cc65/6510 through Peddle: native UCI queue/target lifecycle, REU bank boundaries/nonoverlap/guards, exact transferred count, short/stale/error/timeout/unknown-handle outcomes, count/status parsing of21h/22h, no512-byte WRITE regression, immutable accepted-request buffers, first error through capture/close/report failure, finite cleanup. Host mocks supply storage but actual native code formats/copies/validates.
* Whole output oracle: materialize every A/B/C byte, independently parse via dos_disk_inspect.Volume/inspect, compare every source payload/attributes/write time/archive variant and owned generated startup text; full FAT ownership/free-count agreement; free/raw padding zeros; no extra file, lost chain, unsupported metadata or original-source mutation. Cross-check with a second FAT tool/reference, not only the generator's own mapper.
* Genuine DOS3.3 native Peddle: boot derived A, VER, DIR C/root/all archive directories, PATH utilities, CHKDSK allocation/free counts, GW-BASIC file write/close/SYSTEM, C file COPY/execute/reopen, both profiles, dismount/restart retained writes. AfterB support, independent A/B reads/writes/parameters/status and source separation, DIR B, applicable DISKCOPY/FORMAT semantics or explicit unsupported outcomes. No direct DOS API host implementation/injected guest copy service.
* Physical C64U PAL/Manual64: new owned source clones/output directory, current matching native purpose proof and firmware/REU guard, measure each actual load/plan/emit/close/reopen/verify phase and protocol count. Retain originalRAM/wholechanged4MiB/allsourceimages/newdiskfiles and uncertainty before cleanup. Independently reopen outputs and inspect whole20MiB on host. Verify sourceclosure, settings/media/reset/resume and complete originalREU restoration in development harness. Do not infer elapsed time from64MHz or protocol-call reduction.
* User end-to-end: standalone SETUP runs from native C64, selects user floppy files/2or20MiB/output, creates a new owned configured emulator; normal LOAD/SYS starts genuine A+C/B once supported. Human uses DOS/games/editor, changes files, saves/restarts and sees them. No host REST/runtime network dependency, dummyD81 action or DOS emulation during installation.
* Failure durability: cancellation at every file/slab/metadata/close boundary retains exact first failure and bounded cleanup; incomplete output not advertised as installed; existing files never overwritten. New config/manifest is published only after all referenced outputs verify. Rename is a separate firmware guarantee to investigate, not assumed atomic. Power-loss claims require separately measured tests.
