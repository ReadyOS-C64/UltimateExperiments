# Optional sparse extent container

Keep raw images first. Current HD backend requires an exact2/20MiB EOF and directLBA×512 offsets; a smaller custom file cannot be passed through the existing profile. Firmware writable seeks allocate file space without defining gap contents, and ROOT measured the20MiB raw backing as allocated. Seeking to the last byte is neither sparse formatting nor zero initialization.

A custom container could preserve a virtual20MiB raw sector space using32KiB extents:640 logical extent entries ×4-byte physical offsets =2,560B index (six512B sectors), plus a version/geometry/logical-size/generation/CRC header. Missing extent reads return generated zeros. Writes allocate and zero a full32KiB extent, write the sector, verify payload, then commit the map. Existing extents retain all bytes even after guest FAT frees a cluster; logical FAT freedom cannot authorize dropping nonzero raw sectors. New raw images should zero free space; existing accepted ac1 image may retain deleted-data bytes and cannot be compressed by discarding them while claiming exact raw equality.

Costs: first write into an absent extent initializes64sectors rather than one, plus map/header updates; native code, REU index/cache/ownership and recovery grow. Two index/header generations with checksums are a possible design, not yet an atomic-commit proof. Interrupted payload/map writes, orphan extents, full external storage and corrupt offsets need fail-closed independent controls. Reuse of current cache tags must be keyed by container identity/generation, with exact read-only/mount/uncertain-write semantics preserved.

Benefits would be reduced initial storage/writes on mostly-zero **new** disks; no throughput ratio is known. Required work includes new backend/profile/format version, random logical-to-physical mapping, full raw export/import utility, virtual-sector whole-image oracle, genuine DOS writes/reopen and physical crash/failure tests. Current HDBIOS7B slack cannot absorb it; actual link evidence is mandatory. Compression inside extents and FAT-aware reclamation add still more scope. Defer until raw native SETUP and B persistence are accepted.
