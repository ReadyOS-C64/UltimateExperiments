## Behavior

The native CPU samples TF at a genuine instruction start, retains the sample across bounded prefix/REP host yields, and services a due type1 at the next scheduler boundary. Existing external IRQ polling wins first; a nested type1 precedes that ISR's first opcode, as Intel1979 specifies. Software INT/INT3 similarly preserves sampled trace despite clearing currentTF during entry. Newly enabled TF from POPF/IRET waits through the following instruction; clearing TF in a traced POPF still produces one trap. The accepted-INTR hook captures newly enabledTF even before an ordinary instruction has sampled it. HLT wakes at the type1 boundary; WAIT's test cycle retains originalIP/no retirement. Repaired original segment MOV/POP suppress their own trap while STI does not. REP traps after one eligible element, using the existing original opcode-minus2 prefix-loss restart convention. Type1 entry is not an extra retired instruction. IVT/partial-stack host faults are terminal and retain the already completed IP; no retry or later instruction is allowed.

The focused suite covers those paths, all256 host-status combinations, actual PIC INTR priority, finalCX0/zeroCX REP, repeated prefix yield, moving CS, and the real cold copy. Existing full-TF flag tests retain their original values: they now install a normal guest IRET handler, assert real nested frames/returns, and account for the handler's retirement. No blanket TF masking or host callback replaces guest execution. Flush/invalidate the coherent fixture setup before legacy raw backing-REU writes.
