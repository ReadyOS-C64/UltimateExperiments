# Insert PLAN and cold journal recovery component

Private component, not the complete Insert controller, a released disk menu, or physical acceptance. The changed production sources are `runtime/phase/media_plan.c` and `cold/gate/journal_gate.c`. Regenerate every native alias, prefix binding, capsule, asset checksum and release descriptor when composing them with a different runtime. Do not copy generated cross-role addresses.

The native PLAN now accepts an old selected descriptor with canonical geometry and loaded=0, or an all-zero descriptor only for a never-configured B drive. A null A or null previously configured B is refused. A new B binding sets only its presence bit; existing selected-path, readonly and image-CRC rules remain. Source old CFG must still equal the separately staged original, and the actual caller receipt must match path, drive, old42 and CRC. A legitimate image CRC of zero remains valid.

The D64J ABI is unchanged: version1, 128-byte header, reserved byte7=0, OLD/NEW576-byte CFG records and the existing journal checksum. Inserting a verified existing image and saving a new image have the same durable recovery operation: install the checked NEW binding to the exact verified image. No new journal action selector is needed. The cold gate checks OLD's selected descriptor against OLD CFG presence, requires NEW's selected disk present, and permits only the selected presence bit in addition to the existing selected path/protection/CRC/body-checksum differences. Other home/C/drive fields remain exact. RFW source is unchanged and relinked against the new gate exports.

Six actual runtime PLAN groups check first B, first B with CRC0, ejected A/B, mounted-format compatibility and four invalid snapshot/receipt controls. They compare complete OLD/NEW/journal outputs, high96, C FILES25, zero file commands and all4MiB outside the documented planner output spans. The actual resulting files feed nine cold SYS/JG/CIA/RFW tests: five positive classifications through confirmed rollforward, returned worker frames, original RCV reinstall, fresh NONE, INO and normal handoff; four signed/corrupted refusal cases. The positives preserve the whole third floppy and reserve, exact image/archive bytes, known closed context, software stack and captured effective CPU ports.

These tests deliberately use synthetic verified-image caller receipts and valid synthetic FAT media. They do not execute the incoming worker, WIRE/native COMMIT, the whole Insert UI, genuine DOS, or hardware. Root still owns the combined private-intent → PREPARE → incoming verification/private receipt → CANCEL → re-PREPARE same arena with derived CRC → PLAN → WIRE Insert mode4 → separate Insert BIND/native COMMIT composition and guest DOS revalidation.

Its five errors and one passing negative group are retained in `runtime/PLAN_FIRST_TEST.*`; the observer now checks the exported error and actual exact outputs. No SUT change was required. An initial build used the wrong outer working directory and did not start a compiler. The first parent-pin script assumed every manifest entry used a size/hash object; c115 uses hash strings. Its corrected independent review checks all incoming4105, combined3241 and installer3811 pins exactly. No failure is relabeled a pass.

`closed-plan-journal` captures sources, compiler-discovered C++ SDK headers, cc65 includes/library, fixture inputs and six tool identities before fresh native and model builds. It rebuilds and byte-compares the native products, removes UNIT products before execution, reruns the15 actual groups and checks source/copy/product identity afterward. `close_insert_plan.py` is a single-use historical runner and refuses an existing output directory. A fresh sibling with the same explicit source graph is needed for replay.
