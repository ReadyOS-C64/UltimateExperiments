Scope: restore existing R28 complete-line reuse after C35 classified a retained

## Inputs and result

C21 only after actual C35A0/ERROR0 calls the released133-byte capture helper.
The helper requires the query's still-live bit32, settled query/proofA5/CRkind;
it revokes bit32 before packing, publishes CRC85 and rearms32 last. Cset skips
outgoing publication. C21 copies the real BQ_NEXT3 and CR outgoing bytes34..39
into GSC_INCOMING9, and sets GSC_CAPTURED2. Neither CP_VALID1 nor79 parser bytes
are created. The incoming/outgoing state is genuine producer parser output.

R19type2 requires actual owner4, sealed C24 capability, checked current source
and typed FE guard, ARM/proof flags with no LOST/MUTATING/ACTIVE/undefined bits,
queue0, all13 live arena/ticket/incarnation bytes and descending-index CRC85.
It requires actual logical START equal to the current physical anchor and skips
FAST_PAINT2 so the old witness survives a dirty transaction. It emits the existing
64-byte NEXT+carry6+key28+TOP schema with CRC and VALIDlast. Key comes from the
actual guarded GP_HEADER, never GSC_CURRENT which overlaps the new85B proof.

The original real C24 path remains type1. After an edit, the queue/LOST state
forces actual C24, so R28 VERIFY still checks a real CP_VALID1/fullkey/NEXT and
six carry bytes against the old outgoing witness. No C24 hopper-line is added.

Fresh C21 BEGIN and legacy fallback clear capture/proof. The painter transition
also clears bit32 before its GSEM workspace is reused. No new persistent RAM,
BSS, ZP, bank or asset is used.

## Final measured fit

Same resident/binding as immutable001942 product (940deed/8a28):

* C21 4081B including current-main early TRIED mark, cache-miss latch, capture133,
  type2 copy/hook and prepaint revocation.15B spare.
* R19 4094B (old4028),2B spare; range/journal compiled input objects unchanged.
* C35 PAGE_REUSE4075B, independently released by fileio_service. No query edits
  by this lane. All default profile/source guards remain that lane's authority.

R19 space comes from sharing its complete64-byte request initializer for the
VALID1 write, one unchanged sealed-C24 check before either publisher instead of
performing it twice, and internal offset arithmetic. Incoming header page6 is
even, all outgoing pages7+8*row are odd; that selects S/C magic for all22 rows.
VALID offset low byte is only0 or40, so OR3 equals adding3. These assumptions
are internal writer inputs, not arbitrary public offsets. Full old/new serializer
differential covers both incoming slots and all22 outgoing slots,256 vectors
each. Current GP_HEADER key equals legacy GSC_CURRENT after the retained exact
28-byte comparison, so using the former serializes identical legacy bytes.

## Qualification and boundaries

Final public15 uses the actual sealed images, public root input/render/service,
forced-full comparison, independent bitmap/attributes/source oracle and whole
16MiB guard. All Plain typing, repeated publication, heading/inline/BASIC,
linebreak refusal and prefix cases pass. This restores the observed regression;
it does not establish general reflow or native latency.

Component proof starts with actual public C35 query and actual C21 STEP capture;
no parser output/carry is supplied by host. It proves22 row-offset publications,
368 capability/certificate/owner/source/epoch/queue/flag refusals, opaque
GSEM/BQ/reader state on refusal, no refused REU writes, exact source/shim/leases
and whole16MiB outside the single declared64-byte record on positives. Provider
epoch failure is correctly detected by the outer loader before R19.

An additional pure serializer differential uses fresh actual-startup old/new R19
fixtures and the actual admitted internal factory. Its synthetic carry vectors
test serialization only, not parser semantics. Each variant runs6144 cases,
all final64-byte records agree with an independent CRC/schema model and with
each other; whole16MiB outside24 exact record ranges is unchanged.

Original R19 was privately relinked byte-identical to frozen SEO payload before
experimentation. The first extra serializer attempt tried duplicate import,
which the product correctly refused; that harness trace is preserved. Final
proof uses fresh startup fixtures, with no duplicate import or loader bypass.
