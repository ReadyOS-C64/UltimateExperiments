This packing deliberately differs from R27's full8000-byte bitmap/1000attribute
layout. A literal source capture changes the packed-body CRC; a subsequent
preview falls back to its full producer. GCC_VALID stays0 during preview, so
source reentry follows the original source repaint/capture contract.

Header: signature PV/version1, VALID5, FEhandle6/physical7, full59-byte actual
R14 source identity8, settings64 at67, canonical top131, fold-valid134/full
5-byte token135/count140/generation142, bottom144/count147/all66anchors148,
bodyCRC214, fontREADY216/twoFDhandles217/physicalmaps219/epoch221,
headerCRC223. CRC16-CCITT-FALSE is the existing resident CRC implementation.
VALID=1 is the last checked DMA write; header CRC is computed for that value.

Every pending slice holds its own counted actual R14 source lease and guards
full tokens/epochs/generation/revision/pending shape. Retained GS_FS permits
existing resident missing-worker/STOP cleanup. It also authenticates current
FE and FD ownership/mapping/epochs and fold typed capability/count extent.
The font witness follows the existing admitted FD pack/window identity;
it does not replace overlay CRC or hash all74432 fontpack bytes on each hit.

Lookup fetches128+97 metadata bytes then CRCs<=128 cached body bytes per STEP.
Only after all7920 bytes match does the same foreground slice perform the two
live DMAs, with no yield between checksum and use. IRQ does not mutate REU.
Capture CRCs<=128 already-painted live bytes per STEP, copies the two payloads,
then untrusted header, then VALID1. Optional capture failure cannot reject an
already-completed source rendering; failed lookup guards preserve live body
and never admit unverified cached pixels. Foreign/stale allocation is never
freed. Source rowpackets0..B1FF and chrome/status remain outside the cache.

Fault injection is an integrity/error-recovery test, not an adversarial
security guarantee. A coordinated mutation with recomputed CRC is outside
both this cache and the existing loader's integrity model.
