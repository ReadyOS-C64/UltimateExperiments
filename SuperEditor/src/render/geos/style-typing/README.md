# Local GEOS typing modules

C6 certifies the pre-edit packet; R30 owns the synchronous transaction. C32 is
a sealed data image whose executable payload runs at `$5000`; it is never a
nested C overlay. Eight-pixel code rows use the separate R31/C31 pair.

`build.py OUT PRODUCT_ROOT` links C32 first, emits exact length/CRC constants,
then links R30. Make builds C6 with the normal window target. Every image binds
the resident. Historical frozen sources without `two-color.s` rebuild their
six-vector worker exactly; current sources require all seven fixed vectors.

The JMPs at `$A020,$A023,$A026,$A029,$A02C,$A02F,$A032` are admission, current
context, cache slot, cache read, cache write, status, and exact two-color check.
The combined stack verifier authenticates and decodes every destination from
byte-identical private reassembly, including the frozen BSW9 width table.

The stage window uses namespace42 and its provider/asset witness at `$5FE0`;
C31 uses namespace41. Legitimate writers revoke that capability before writing.
Cold entry checks ownership, binding and raw CRC; warm use retains that witness.

C6 publishes VALID2; both R30 entry and guard require2. Old generation1 modules
must decline this certificate even when their resident binding is identical.
CRC-covered byte44 is0 for the existing strict-white proof,1 for conditional
shared-tile election. Neighbor-scan failure restores the original row before
sealing. Unsupported certificate modes decline.

Mode0 retains strict attributes and one transform. Mode1 first computes a dry
caret-free provisional row, then counts actual white/yellow ink across both
physical tile bands. Source inverse is already present; selection/caret is
excluded. Only unchanged color winners admit. Unsupported roles, geometry,
syntax, selection/folds, or actual winner changes fall back before publication.
The public pixel primitive still applies its original strict validation.

The transaction updates chars/styles/X boundaries, rebases later prefixes and
publishes packet/header/caret/status only after admission. No resident state,
BSS, zero page, bank or object is added. Current C6=3654, R30=3662,
C32=3803/raw3771 after the warm-shift optimization. The Plain admission extension accounts for6/34 added bytes
in R30/C32; C6 is unchanged.
The helper uses temporary8A00/8000/8400/8580/8640 scratch in owner4; see
`two-color.inc`. All font inputs are immutable and authenticated in evidence.

The existing byte-plus-residual deletion optimization remains. Actual pixel,
source/history, failure/recovery and wholeREU oracles govern correctness;
instruction counts do not establish native cycles or physical key latency.

## Plain source admission

C6 already certifies ordinary Plain source rows with VALID2. R30 now admits
capability values0,1,3, refusing invalid2 and values4 or greater. Plain C32
additionally requires no inline marker and every actual packet style byte zero.
The stored BSW9 encoding is0; internal semantic context kind9 is unrelated.
The existing guard independently bounds count1..160 before the packet loops,
and retains source/token/epoch/revision, packet/header, role0, font CRC, X/width,
grammar, tile seam and publication checks. No parser certificate is invented.
Full and Markdown keep their styled paths. Selection, stored folds, unsupported
geometry/metadata and CR/reflow cases retain the ordinary renderer.

The earlier Plain-admission60-image CPU matrix checks46 frames and8 API faults, including
repeated edits, literal controls, marked replacement, preset invalidation,
Full/Markdown, checked-packet corruption, and namespace42→41→42 stage reuse.
Independent pixels, forced full rendering, source/history and precise whole-REU
guards agree. Both new images pass the complete60-image/staged stack analysis;
the declared relative foreground-plus-interrupt bound remains68 bytes.

Native PAL same-input Full/Plain INSERT/BACK runs use real File/Open and IRQ
setup, then the disclosed PC/SP/public-input stopwatch through the actual
scheduler. Plain INSERT improves2,264,434→512,064 cycles; BACK improves
2,254,299→180,750, loads21/22→3/4. Full is essentially unchanged at
726,957/183,627→729,907/183,361; IRQ phase contributes small timing variation.
Full is measured before Plain in both runs, with genuine cache state retained.
All four paired PNGs are exact. The test checks512,000 actual VIC pixels,
all60 sealed assets, font pack, source/history/settings/clipboard/reservation,
and four precise whole16MiB pending-pair intervals. It does not establish
general reflow performance, worst-case latency or physical keyboard timing.

Reproduction uses `tests/test_geos_plain_typing_candidate.py --fixture FIXTURE`
and `tests/test_geos_plain_typing_registered_vice.py` with explicit sealed
control/candidate fixtures. The native test requires only GTYPE/TYPE to differ.

## Warm byte shifts

For advances1..7, the bitmap suffix loop shifts only the current byte and its
immediate neighbor. Insertion advances8..11 first select the preceding byte,
then shift the remaining0..3 bits with the second neighbor. Row edges still
supply zero rather than reading outside the40-byte row. Existing deletion,
prefix/tail masks, traversal order,9-row seam and publication guards remain.
Only C32 code and R30's embedded C32 length/CRC constants change; vectors,
resident state and allocation stay the same.

The component gate covers2154 cases plus17 seeded cases per variant, with
pixel equality and no instruction-count regression. Public style, selection,
no-wrap and refusal gates retain independent/forced-full pixel comparisons,
source/history, whole RAM and precisely bounded full16MiB REU checks. The
composed registered62 package also passes source-aware rebase protocols,
real24-transaction journal boundaries and the68-byte stack bound.

The native PAL A/B gate captures48 actual screens: repeated INSERT/BACK and
caret moves in Plain prose and Full strong text. All24 paired PNGs are exact.
Steady Plain keys improve3.4–3.7%; strong keys4.1–4.4%. First insertion improves
only0.9–1.5%. Unchanged caret code has IRQ-phase variation, including a0.6%
regression retained in the report. This is a small measured improvement;
whole-key latency and broad reflow remain open performance work. Native pairs
use the earlier62 C41 in both variants; separate canonical CPU gates verify
composition with7654's journal/applicability fix. See docs/PERFORMANCE.md.
