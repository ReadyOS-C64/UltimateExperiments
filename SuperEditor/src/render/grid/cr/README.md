# Plain newline transaction

R29 handles a validated Return split or BACK merge in a visible Plain60/80
paragraph. It stays in one operation while it compares source, stages changed
packets and paints. C33 performs the existing status update and R25 remains the
only final NC header publisher. Styled, selected, folded, panned or incomplete
offscreen contexts retain the ordinary renderer.

The resident imports DOS file `ROW` during genuine cold startup. Its filename
aliases the existing `GEOSROW` suffix: one additional packed two-byte catalog
entry, no new filename string or warm state. C29 lifecycle remains independent.
All60 assets fit the existing four managed code allocations and64-entry catalog.

Admission preserves the real R25 source/header/font checks. R29 checks owner4,
the exact FS59 source tuple, provider epoch and FE ownership, old header equality
and CRC, and every old packet used. It compares the genuine pending source
against the checked old bytes, consuming or skipping exactly one CR. It stages
all candidate packets and anchors before painting. Exact240-byte row equality
allows pixel reuse; matching CRC alone never proves content equality.

The native backend's actual1024-byte narrow font is copied once to `$5000`,
after catalog/owner/epoch/size/CRC checks. Its bytes must match a generated CRC
from that same sealed backend font. GEOS stage readiness is revoked before the
copy. The local role0 blitter uses the shared PETSCII converter and retains all
inverse/selection/caret XOR combinations. There are no per-row overlay swaps.

The uninterrupted owner4 call borrows retired LINEINDEX scratch. All three
index-readiness fields are cleared before borrowing; no active source lease,
worker continuation, callback or foreground yield is permitted. `$9000-$90EF`
holds one old packet only during that loan. Candidate packets use exclusively
owned FE `$4000-$549F`; published NC/SP2 and old packets remain unchanged until
paint begins. Cache validity is revoked before the first paint. On failure the
ordinary renderer repairs invalid derived state. Complete anchors/CR bits and
row CRCs are published only after paint; R25 then commits VALID last.

`tools/grid_cr_font_witness.py` checks actual sealed R16/R17 images and fonts.
The normal build regenerates R29 binding aliases and C33/R25 witnesses from
the linked resident. No resident address or physical REU bank is hard-coded.

CPU checks use `tests/test_grid_cr_registered.py` against the exact packaged
product. They execute the actual60-name startup loop with the existing ROM
transport seam, without importing a60th image after startup. Public split/merge,
edge/history, refusal/recovery and unchanged-route cases check independent
pixels/packets/anchors, source/history and exact observed DMA/whole16MiB guards.
Native timing and real IRQ qualification are recorded separately from CPU
instruction counts and physical keyboard latency.

`tests/test_grid_cr_registered_vice.py` compares eight native PAL split/merge
cases against the committed59-image control; every paired screenshot is exact.
The measured reductions are38.1–39.9% at60 and20.4–22.4% at80, loads9→4.
`tests/test_grid_cr_irq_vice.py` separately exercises actual IRQ Return, Undo,
Redo and immediate BACK in both widths, without a PC/SP substitution. All eight
frames pass the complete source/history/settings/font/catalog/shim and native
VIC oracle. The BACK is still a pending edit until flushed; a restored byte
string alone does not imply a clean history state. Two real Undo commands
return this scenario to its saved node before opening the next file.
