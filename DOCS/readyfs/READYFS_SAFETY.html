ReadyFS C64 Ultimate Test Safety

Non-negotiable boundary

Each automation run receives a unique run id and two optional owned roots:

  • /usb1/READYFS_TEST/<run-id>
  • /sdcard/READYFS_TEST/<run-id>

The host setup creates the root and a marker containing that exact run id. Before a destructive command, both the normalized path prefix and marker must match. Prefix-only checks are insufficient. Symlink-like escapes, parent components, aliases that expand outside the root, and image boundaries whose host image is outside the root are rejected in automated destructive suites.

Tests may create and remove leaves inside their own root. Run roots and logs remain after the suite unless an explicit cleanup request names the exact run id and its marker validates. Existing USB1, SD-card, disk-image, and IEC-device content is never a cleanup target.

Ultimate access

C64 Ultimate REST/FTP commands run only from a Terminal-owned/background bash. The suite records the original Ultimate configuration before enabling Command Interface or Software IEC and restores it on every exit path.

UCI transport

ReadyFS follows the transport proven by ReadyIRC and UCI Tester. Commands start from fully quiescent IDLE, PUSH is asynchronous, both queues are completely drained, DATA_ACC must visibly advance state, ABORT is requested once and then serviced, and completion includes the final quiet-idle wait. Poll counts bound failure; they never pace commands. Physical acceptance runs at 1, 16, and 64 MHz.
