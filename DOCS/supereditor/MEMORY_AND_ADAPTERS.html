Overlay calls and measured sizes

SEO2 images contain a 36-byte checked header followed by at most 4096 payload bytes, including a 16-byte resident-binding signature. The resident loader validates slot, ID, size, entry, binding and CRC before executable replacement. A cached image is a checked logical REU allocation, not a persistent RAM pointer. A call supplies the resident frame; modules must not retain pointers into another evictable image.

R-slot 0 is $A000, C-slot 1 is $B000. Same-slot nesting is rejected. C→R nesting is allowed; calling C from an active R is rejected. A root scheduler therefore sequences C workers instead of nesting them. IRQ/NMI handlers are resident and do not load overlays or DMA document state.

REU provider, document limits and DMA

The standalone provider probes capacity, then maintains logical→physical maps, typed ownership and an epoch. Bank 0 is reserved by this provider; it is not an application scratch shortcut. Objects carry ID, generation and provider epoch, and split checked transfers at logical-bank boundaries. Never substitute an object ID, logical handle or file number for a physical REU bank.

The ordinary se_reu_copy buffer must fit wholly in $4000–$BFFF, have a nonzero exact 16-bit length and stay in one 64 KiB REU bank. It validates the full request before writing REU registers and briefly masks IRQ around the DMA. The one-byte presence probe and lifecycle copier have separate narrow contracts; their special handling does not widen the general DMA API. Document readers have stricter phase/buffer rules as well: a physically legal address does not establish ownership of VIEW, NAV or another live phase.

The engine allocates metadata plus separate original and append objects. Its source quota derives from the original object's admitted bank count. Pending insertions and their eventual append interval are checked before mutation; full-capacity refusal must preserve the pending edit, caret, selection and usable Undo history. Capacity is not the same as free physical REU space.

Actual historical full-feature cold-boot/edit/save evidence exists at 1 MiB and 2 MiB; the full font configuration refuses 512 KiB and missing REU. The native 64KiB boundary gate verifies a one-bank quota, early refusal, replacement, Undo/Redo and byte-exact 65536-byte SaveAs/reopen. These are tested configurations, not a promise that every document/history/clipboard combination fits 1 MiB. The standalone gallery uses 16 MiB. Allocation counts at checkpoints are not transient high-water measurements.

Observed foreground stack

The immutable 39-asset run passed 128 seeded rounds and 183 canonical/integrity checks, including all four modes, insertion/deletion, Undo/Redo, clipboard, fold/preview churn and source offsets above 64 KiB. It sampled 2,593,027,928 instructions across 101,364 foreground calls. No observed push wrapped SP.

The deepest sample was SP=$DE: 33 bytes used from $FF, including the two synthetic caller bytes. The remaining stack address range is 223 bytes ($0100–$01DE); this is numerical headroom at an observed sample, not a proven native reserve. It occurred while public RIGHT (command 2) drained job 2 in GEOS: se_editor_service, with C4 eedit and R2 engine loaded. The actual deepest instruction was JSR at $21BE (se_object_validate) to $21A0 (object_service_valid). Catalog indexes were 1 and 6 respectively; indexes are not module IDs.

The stack workload's final source SHA256 was 2d9f24a314b12c703974431563ce307087c0ace83f67678ed7fc55159207117c. No pixel or emulated-cycle claim is derived from this instruction experiment.

The CPU harness starts each callable service at SP=$FD, with two synthetic return bytes in $01FE/$01FF; reported usage from $FF includes those two bytes. It executes real editor instructions, including checked overlay loads, and records SP before and after every instruction. It neither patches editor code nor substitutes a host source/history implementation. Explicit fixture source/font imports and ROM IEC seams are excluded from the measurement.

The seven-instruction calibration reaches SP=$F9: the two caller bytes, one nested JSR, PHA and PHP require exactly six bytes. This catches a probe which samples only entry/exit and misses the deepest push.

This is observed foreground depth, not a static worst-case bound. CPU interrupts are masked in this experiment. The separate native PAL/NTSC timing gate compares $0100–$013F before/after real IRQ-driven operations; that proves those 64 bytes stayed unchanged in those samples. It does not identify the lowest transient SP or establish a universal 192-byte native bound.

The resident IRQ handler calls KERNAL UDTIM ($FFEA) and SCNKEY ($FF9F), then returns through $EA81. Its comment/ABI expects the KERNAL dispatcher to have stacked A/X/Y; each handler JSR itself pushes another two bytes, while ROM helper nesting is outside this CPU probe. The NMI handler adds exactly three software pushes and no JSR; the 6510 interrupt entry adds three hardware bytes. Those local facts do not bound upstream ROM entry, NMI interrupting an IRQ, repeated NMI edges, or IEC OPEN/CHRIN/CHROUT/status/error paths. This historical probe alone claims no audited combined IRQ/NMI/ROM maximum. Its original follow-up requirement was verified ROM-revision call-depth analysis or instruction-level native tracing covering those paths, not subtraction of a guessed interrupt allowance.

Lifecycle and future OS integration

The current47 standalone adapter has native four-mode capture/restore and continued editing/SaveAs/reopen evidence, including affected preview-cache revocation tests. Its versioned C29/R26 contract remains the one described below; the current checkpoint identifies all exact build scopes. This is a controlled standalone adapter, not a ReadyOS application switch.

The original 41-image candidate contains a standalone, same-process C29/R26 adapter. Its current contract uses an FC-typed logical snapshot allocation, a versioned header, resident binding, provider/source witnesses and a fresh trusted low-RAM thunk. Capture and verification steps process at most 256 payload bytes or one provider table. The final trusted thunk restores the complete fixed extents and transfers control; that final commit is not a 256-byte step. Restore verifies before publishing and resumes at a fresh editor event loop, never at a saved C/R-slot PC or saved CPU stack. Its exact-extent copy is deliberately separate from general DMA.

The fresh control region includes bounce $0700, binding/descriptor $0800, restore thunk $0900 and resume prelude $0A00; these are cold-only facilities, not new warm allocations. The current primitive assumes its live provider and backing REU remain owned and its known interrupt hooks are not externally raced. Actual standalone scramble/resume tests belong to that adapter's own identity/evidence. This document's 39-image stack/native gates do not establish 41-image lifecycle, power-loss recovery, OS switching or hardware readiness.

ReadyOS currently snapshots $1000–$C5FF; its existing shim alone does not preserve $CA00–$CFFF, editor ZP, color RAM, vectors or hardware state. A future adapter must explicitly preserve the second extent, coordinate provider-owned allocations/epochs, reinstall runtime hooks and refresh display/input state at an OS safe point. It must replace the standalone allocator/probe, not rerun cold provider initialization over live mappings. The editor remains excluded from $C600–$C9FF. No ReadyOS registration or C8xx calls are implemented here.

UltimateDOS belongs behind the existing bounded open/read/write/status/directory transport seam. Keep filename/device binding, acknowledgement, staging, verification and atomic source publication in the editor coordinator. Replacing IEC transport must not flatten canonical source, bypass ownership checks or convert PETSCII data into host text. D81/KERNAL transport remains the current standalone implementation.
