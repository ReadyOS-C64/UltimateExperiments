Native rules that implementation and tests must respect:

1. UI is version-only on SD2IEC; identify sd2iec or uiec, not drive ROM M-R.
   UI has different reset semantics on other IEC devices.
2. Explicit partition FAT references avoid global cwd changes: file
   `1//folder/:file`, directory `$1//folder/`, scratch `S1//folder/:file`, mkdir
   `MD1//parent/:child`. Native partition0 aliases the selected partition; do
   not silently reinterpret existing `10:/file` as FAT partition1 root.
3. Rename cannot cross parent directories. Cross-folder MOVE must verified-copy
   then scratch. Stage and backup filenames must remain in destination parent
   and partition, not the existing unconditional `N:/rf~XX` root.
4. RD rejects every slash: enter parent, then `RD1:child`. A cwd restoration
   strategy is needed. Native success is operation-specific: scratch/RD may
   return01; configuration03; partition select02; version73.
5. G-P is exactly31 binary bytes. Byte0 type, byte2 partition; labels3..18;
   size27..29 in512-byte units; byte30 CR. Type1 covers BOTH FAT and mounted DNP;
   types2/3/4 denote D64/D71/D81. Type1 alone cannot prove no image is mounted.
6. Mount/unmount closes all user data buffers on the SD2IEC, across partitions.
   Establish image state before OPEN. Flat images use `P:leaf` and `$P`, not
   `P//...`; their CD-root fails. Unmount flat image with `CDP:`+$5F; DNP needs
   known root first. Current translator unmount loses partition and is wrong.
7. Image and containing FAT storage, or two images on one partition, cannot be
   streamed simultaneously. Need whole-file spool and switching, or verified
   staging on another available endpoint for files exceeding spool capacity.
   Automatic `!` paths need native transaction control and honest restoration.
8. Validate native component syntax, not just length: reject injected `:`, `,`,
   `=`, CR and unintended mutation wildcards. Common native buffer is120 bytes;
   compound rename must fit, not merely each234-byte directory path.

### Configuration scope

Proposed new `IEC device: subcommand` family leaves existing NATIVE translation
preview unchanged. Version/status, config, partitions/G-P, partition query vs
explicit selection, address [--save], extensions, hiding, image presentation,
wildcards, save-config, initialize, soft/hard reset, and bounded raw DOS/hex
escape hatch are in scope. Do not silently change settings on probe or COPY.

Exact -36 encodings: config query `X`; long version `X?`; extensions `XE0..4`;
hiding `XE+/-`; image presentation `XI0/1/2`; wildcard `X*-/+`; persistence `XW`;
address U0> + binary unit; initialization I; soft reset UJ; hard reset U+$CA.
Bare XE or XI MUTATES to zero and is not a getter. XT, X8 and X9 are unsupported.
XW saves all supported current extended settings, not just the last change;
it does not persist cwd, current partition or mounted image. CP also clears an
autoswap list. Address change must check collision, close channels, verify new
address, then optionally save and invalidate old/new cached assumptions.

### Ultimate namespace trap

Target5 opcode$12 is SAVE, not GET_PATH. Never send it as a read-only query.
DOS targets1/2 GET_PATH are separate path objects. `/v1/drives` SoftwareIEC
partitions[].path exposes actual runtime cwd; native `CD0:`+$5F restores its
configured root even when the media is absent. See local reference firmware
`software/io/command_interface/softiec_target.h` and `software/io/iec/iec_channel.*`.
